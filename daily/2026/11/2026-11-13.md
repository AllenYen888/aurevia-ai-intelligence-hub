## 重點摘要
GitHub 於 2026-11-09 公告，GitHub Actions 工作流程執行結束後，可掃描執行日誌中的特定供應商金鑰格式。偵測到的內容會進入 Secret Scanning alerts，並連回相應工作流程日誌。這是企業付費安全方案的公開預覽，不是所有 GitHub 免費帳號皆可用。

## 三個重點
1. 工作流程結束後才掃描日誌；不會回溯掃描啟用前的舊紀錄。
2. 警示可連回工作流程日誌；即使日誌刪除，警示仍可能保留。
3. 僅供 GitHub Enterprise Cloud 搭配 GitHub Secret Protection 或 GitHub Advanced Security 的企業使用；需由企業擁有者啟用，預設關閉。

## 實作步驟
1. 一般使用者先檢查 Actions 執行日誌，避免在 echo、除錯或錯誤訊息中輸出 API 金鑰與存取權杖；使用 GitHub Actions Secrets 存放憑證。
2. 符合授權的企業管理員至 Enterprise settings → Policies → Advanced Security，於 All repositories 選擇 Enabled；確認儲存庫已開啟符合授權的 Secret Scanning。
3. 在新完成的工作流程後檢查 Secret Scanning alert list；發現洩漏應撤銷並輪替金鑰，修正工作流程，並依組織程序處理。

## 適用情境
美業與中小企業的 AI 內容自動化、GitHub Actions 排程、CRM 與社群平台 API 整合；尤其適合管理自動發布的技術團隊。

## 成本、限制與注意事項
- 新的 Actions 日誌掃描為公開預覽且有企業授權門檻，不可宣稱免費帳號已開通。
- 不掃描啟用前的舊日誌。
- 不偵測通用格式、自訂格式、AI 偵測的金鑰，以及已被 Actions 遮蔽的憑證。
- 預覽期間日誌警示不會主動發通知，須自行查看警示清單。
- 即使使用秘密掃描，仍應遵守最小權限、遮蔽輸出、定期輪替與事件應變。
